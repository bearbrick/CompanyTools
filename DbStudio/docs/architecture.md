# 产品架构与演进边界

本文说明 DB Studio 的运行边界、代码分层和必须长期保持的产品约束。它不是文件清单，而是新增功能与评审代码时共同遵守的设计基线。

## 总体结构

```text
Blazor 页面与组件
        │ 只传意图、稳定 ID 和并发版本
        ▼
StudioStore / SqlServerTools 应用服务
        │ 统一授权、事务、版本和审计
        ├──────────────► SQLite：项目、账号、快照、发布记录
        │
        └──────────────► DacFx / SQL Server：读取、比对、受控部署
        ▲
纯领域服务
校验、差异、搜索索引、ER 布局、SQL 与归档生成
```

- **表现层**只维护交互状态，不直接访问 SQLite、拼接部署 SQL 或决定权限。`Home` 的不同业务操作按 partial 文件拆分；可独立复用的区域继续提取为组件。
- **应用服务层**是安全和一致性边界。任何写入都在这里重新授权、核对项目归属和修订号，并在同一事务内写业务数据、修订快照与审计。
- **领域层**优先使用无状态纯函数。输入是已保存快照，输出是校验结果、差异、搜索结果或布局，不修改调用方对象，也不依赖当前页面。
- **基础设施层**隔离 SQLite、SQL Server、DacFx、PDF 和浏览器互操作。数据库部署只执行服务器保存且通过漂移复核的计划，浏览器不能提交任意 SQL。

## 核心数据不变量

### 修订与发布

- `r` 表示设计文档修订。只有项目设计实际变化时递增，每个 `r` 保存一份 Brotli 压缩的完整快照。
- 恢复历史不会倒退或覆盖原记录，而是以历史内容创建新的 `r`。单表恢复只替换目标表。
- `V` 表示已经在数据库完整验证过的不可变发布快照。只有设计到数据库部署成功，并且管理范围内结构再次全量一致时，才创建或复用 `V`。
- 从数据库反推到设计只产生普通 `r`，不产生 `V`。每个连接独立保存最后一次部署状态及对应的 `r / V`。

### 关系模型

- 逻辑关系用于设计导航、搜索和 ER 图，不生成数据库约束。
- 物理外键才进入 DDL、DacFx 比对和数据库反推。
- 历史 JSON 未记录关系类型时按物理外键读取，保证升级兼容。

### 权限与并发

- 入口按“有效会话 → 全局权限 → 项目成员权限 → 对象归属 → 当前修订”检查，按钮可见性不能替代服务端授权。
- 保存、项目设置、连接和部署均使用乐观并发。过期页面必须刷新，不能静默覆盖其他成员的修改。
- 数据库密码只以受保护形式存储，不回显、不进入备份、分享、审计或日志。

## 性能策略

- 页面读取版本元数据时按批次加载，默认只取最近 100 条、最多 2000 条；只有比较或恢复时才解压所需快照。
- 字段搜索以 `ProjectId + Revision` 为生命周期建立内存索引，使用稳定 ID 跳转。当前数据规模无需 Elasticsearch；未来只有在跨项目、百万级字段或复杂全文相关性成为真实需求时再引入外部索引。
- 版本差异预先建立稳定 ID 与字段位置字典，避免在循环内重复线性查找。
- ER 布局、搜索、归档与 SQL 生成都读取隔离快照，不能修改已保存项目或编辑草稿。

## 文件与注释规则

- 公开类型、成员和参数必须有中文 XML 文档；`CS1591`、`CS1573` 已升级为构建错误。
- XML 文档解释业务含义、边界和失败行为，不复述代码。SQL、ER、ID、DacFx 等专有名词可以保留英文。
- 页面编排文件保持在 400 行以内；版本存储按架构、历史和部署拆分，每个文件保持在 220 行以内。其他生产源码原则上不超过 500 行，超过时必须按职责拆分或在评审中说明其内聚原因。
- partial 只用于拆分同一个明确服务或页面的职责，不能用来隐藏循环依赖。跨功能复用应提取独立领域服务或组件。

## 质量门禁

提交前至少执行：

```powershell
dotnet build CompanyTools.slnx --no-restore
dotnet run --project DbStudio.Checks/DbStudio.Checks.csproj --no-build
```

构建负责语言、可空性和公开文档门禁；检查项目覆盖授权、隔离、版本、关系、搜索、ER、归档、DDL 和部署边界，并验证关键文件没有重新膨胀。真实 SQL Server 部署仍需在专用实例执行集成检查，不能只用内存或 SQLite 检查替代。

## 新功能落位原则

1. 先明确数据归属、权限、并发版本和审计事件，再设计页面。
2. 可纯计算的逻辑放入领域服务并先写检查；页面只负责组织输入与呈现输出。
3. 所有外部输入在服务边界重新验证，不信任浏览器隐藏字段、下载内容或旧预览结果。
4. 会改变数据库的能力必须经过预览、目标确认、漂移复核、执行记录和失败可诊断五个阶段。
5. 新增长列表必须考虑分页或上限；新增快照必须考虑兼容读取、压缩和恢复测试。
