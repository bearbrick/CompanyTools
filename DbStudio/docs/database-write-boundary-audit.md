# 数据库同步写入范围排查

日期：2026-09-08。范围：当前仓库中的运行时代码、SQL 生成与部署策略、反推与合并、连接配置、导入导出和测试程序。

本次没有连接或修改实际业务库。以下区分代码中确认存在的风险与测试结果，不将代码风险当作生产库已发生的操作记录。

## 结论与修复

业务 SQL Server 的运行时写入入口只有 `SqlServerTools.ExecuteAsync` 中的 DacFx 部署调用，整库和单表共用该入口。此前没有完整限制 DacFx 可操作的对象类型；仅禁止删除账号、忽略权限不足以阻止重建用户。

| 排查项 | 原来的问题或行为 | 当前处理 |
|---|---|---|
| 数据库用户、服务器登录 | 提取忽略登录映射，部署可能把映射差异解释为重建用户；已在离线模型复现 `CREATE USER ... WITHOUT LOGIN` | 预览与执行均排除，不负责创建、修改或删除 |
| 其他安全及实例对象 | 仅枚举排除部分安全对象容易遗漏证书、密钥、审计、链接服务器、端点等 | 使用允许列表，DacFx 新增对象类型也默认排除 |
| 对象所有者 | 旧选项没有忽略授权所有者差异 | 忽略所有者差异；报告中修改 schema 的操作也拒绝 |
| 数据库 DDL 触发器 | DacFx 默认会在部署期间停用再启用，失败时可能无法重新启用 | 显式关闭该行为；独立数据库测试确认建索引时触发器实际触发 |
| 关联视图、存储过程、函数 | 缺少完整排除策略；DacFx 默认会刷新关联模块 | 排除模块变更，关闭自动刷新；越界依赖操作拒绝整个计划 |
| 数据库配置、文件、分区和存储 | 旧代码只显式关闭部分数据库选项，保护不够集中 | 排除数据库选项、文件、文件组和分区对象，关闭配置、兼容级别、数据库排序规则、文件大小脚本；忽略存储位置差异 |
| 扩展属性 | 不能因为类型是扩展属性就允许修改数据库、账号、视图上的属性 | 报告按宿主验证，只允许表或字段属性；不自动清理源中未维护的扩展属性 |
| 任意部署前后脚本及执行扩展 | 当前包由程序构建，没有上传任意 dacpac 的执行入口 | 仍显式禁用前后脚本和部署计划执行扩展，避免以后引入包来源后扩大范围 |
| 预览与执行一致性 | 单表只在离线预览时检查范围，实际执行会重新规划 | 整库、单表预览均校验；执行前针对实际连接只读生成报告，再校验范围及与已预览操作的一致性 |

## 当前允许范围

- 表、字段、主键、普通/唯一索引、唯一约束、外键、默认约束、检查约束。
- 表和字段上的扩展属性；界面生成的说明是 `MS_Description`。
- 为设计表创建所需 schema，不修改现有 schema 的所有者或删除 schema。
- 单表必须通过完整宿主匹配，不能修改其他表；整库只有明确启用清理后才能删除源中缺少的表等可管理结构。
- 需要改变受保护的对象才能完成的部署，停止整个计划，不静默隐藏该操作继续执行。

账号、角色、授权、证书、密钥、审计、链接服务器、服务端点、数据库配置、视图、过程、函数、触发器等不属于当前 Studio 的同步维护范围。表变更可能触发数据库本来就有的 DDL 触发器；Studio 不停用它们，也不绕过其业务规则。

## 其他入口

| 入口 | 实际行为 |
|---|---|
| 测试连接 | 查询数据库名和服务器版本 |
| 比对 | DacFx 读取元数据、在内存生成模型和脚本，审计记录写 Studio SQLite |
| 反推预览 | 查询 SQL Server 系统目录，只读取表、字段、索引和约束等定义 |
| 反推合并 | 合并项目设计并写 Studio SQLite，不写回 SQL Server |
| 项目、模块、表设计保存/删除/复制 | 写 Studio SQLite；需要另行比对和执行才影响业务库 |
| Studio 用户、角色、成员与分享权限 | 写 Studio SQLite，是应用自身的 RBAC，不是 SQL Server 账号管理 |
| 连接保存/删除 | 保存或删除 SQLite 中加密的连接配置，不创建、修改或删除 SQL Server 用户或数据库 |
| DDL、结构 PDF、项目和同步脚本导出 | 生成文件/下载，不自动执行导出的 SQL |
| 检查程序 | 单独项目，生产发布不包含该程序；SQL 集成检查使用显式指定实例和随机命名的专属测试库 |

## 验证

315 项检查通过，包括：

- 用失去登录映射的源包复现旧版重建用户脚本；修复后仍正常生成普通索引，且不生成用户或权限操作。
- 源/目标包含不同视图、存储过程、函数、序列、证书和 schema 所有者，表字段差异仍正常生成，受保护对象不进入变更。
- 未知类型、账号、授权、触发器、无关 schema 和非表字段扩展属性操作会被拒绝。
- 实际计划增加未预览的操作时拒绝执行。
- 独立 LocalDB 实际创建表和普通索引、修改列与说明、再次比对无差异，单表范围和数据丢失保护仍生效。
- 用户 SID、角色成员和授权在单表同步/清理前后相同；数据库 DDL 触发器在创建索引时仍执行。

## 运行影响与边界

- 执行前多一次面向实际连接的只读规划，会增加执行等待时间；普通比对不增加这一步。
- 不自动刷新关联模块，依赖模块的维护需由其负责人单独处理。
- 不自动删除未维护的扩展属性；清空设计说明不等同于授权删除目标上的所有备注。
- 使用更新后的 IIS 发布包并重启应用后，必须重新比对；旧计划不能继续使用。
- 本排查不能证明旧版失败部署已完整回滚，也不能代替对业务库实际状态的只读核对。

## 单表快照误拦截补充修复

同日补充：单表操作原先仍以整库 XML 指纹是否相同作为执行门槛，即使目标表不存在，无关对象变化也可能触发“实际数据库结构已改变”。这说明检查范围过大，不能据此认定目标表被修改；未采集报错时服务器的两个快照，无法反推那一次究竟是什么对象变化。

当前改为：

1. 指纹相同走快速路径；不同则在内存中用 DacFx 对两个快照进行只读语义比较，不凭 XML 字节差异直接拒绝。
2. 单表核验目标表、设计外键目标，以及实际入站/出站外键直接关联的表。整库仍核验整个结构范围。
3. 无关变化不拦截单表；基于最新快照重新叠加同一份已保存设计，保留其他表的最新状态，防止旧基线覆盖并发变更。
4. 执行前继续检查实际计划的对象边界、与预览操作的一致性、项目版本、连接及权限。
5. 真正漂移时列出变化对象；不会自动执行追加变更。

已验证：目标表尚不存在时，无关表并发创建不影响目标表创建；新建后再次比对无差异；目标表被并发创建/修改、说明变更或删除、计划及实际外键依赖变动仍被识别，等价默认表达式不会误报。

含 SQL 集成的检查共 325 项通过（`artifacts/scoped-drift-sql-checks.log`）；随后补充的两个实际外键方向检查也通过，最终不连接 SQL Server 的 289 项检查记录在 `artifacts/scoped-drift-final-checks.log`。所有写入仍只发生在独立 LocalDB 测试库。
